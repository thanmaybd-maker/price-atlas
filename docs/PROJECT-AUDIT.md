# Price Atlas: 15-perspective audit

Reviewed 29 October 2026. These are fifteen evaluator perspectives applied to the code and running system, not fifteen independent people or invented scores. Implemented code, production verification and human delivery are distinct evidence.

The strongest project claim is **honest, variant-aware comparison with recorded evidence under a small collection budget**. Guaranteed retailer access, nationwide delivered prices and a completed 2,500-product catalog are not established.

## Useful optional work completed

- History CSV for the selected product, period and basis, with source URL and original UTC observation time.
- Shareable `basis=item|delivered` and `days=7|30|90` history views.
- Independent history basis, ring pause, immediate lotus skip, safe storage and visibility-aware polling.
- Invalid page/API responses and conservative model/ISBN matching.

## Best next additions, in order

1. Finish human acceptance: Google login, save/reload, an eligible item-price target, the evaluator's own Telegram Start and authorized alert receipt/opt-out. Configuration alone does not close this task.
2. Expand balanced, verified primary-page coverage or permitted official feeds/APIs. Respect retry windows and the 1,000-request ceiling. Getting 2,500 verified products needs source access and time, not generated names.
3. Add database-backed search, server pagination and offer requests scoped to visible IDs as the real catalog grows. Measure before adding a separate search service.
4. Exercise a private PostgreSQL backup/restore with deletion, retention and outbox reconciliation. Catalog snapshots are supplementary evidence.
5. Add pincode checks only when retailer support can actually verify serviceability. A cosmetic pincode textbox would mislead.

## What should wait

- Gemini/AI can later help spelling or intent. It must not invent price, stock, exact variants or evidence. No new model API is needed for the current feature set.
- Browser push is a possible no-domain channel, but needs subscription lifecycle, permission, expiry and delivery tests. Avoid bolting it on just before presentation.
- More themes/3D scenes, rewards, social feeds, fake catalog padding and nonworking retailer counts increase risk without improving comparison evidence.
- More provider accounts/credits do not remove source blocks, permissions, shared app budgets or identity requirements. They are not a presentation reliability plan.
